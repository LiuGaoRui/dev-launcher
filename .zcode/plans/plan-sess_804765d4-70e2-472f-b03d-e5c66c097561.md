# 修复内存清理「手动锁定」重启丢失问题

## 根因

锁定是纯前端机制：PID 数组存 localStorage（`devlauncher:cleaner:lockedPids`），后端无任何锁定概念。

1. **按 PID 索引**：进程重启后 PID 必变，旧 PID 失效，还可能被系统复用到无关进程上
2. **主动清除（元凶）**：`src/stores/cleaner.ts:83-91` 的 `scan()` 每 5 秒轮询时，把「当前进程列表中不存在的 PID」从锁定集删除并立即回写 localStorage——应用重启后首次扫描时目标进程 PID 已变或未运行，锁定条目被永久清除

## 方案：SQLite 指纹锁定表 + 后端匹配（用户已确认：轻量管理、不加 kill/trim 护栏）

锁定改为持久化**进程指纹**（cmdline 优先，cwd+name 兜底），与 PID 完全解耦。锁定与匹配用同一后端函数计算指纹，PID 变化不影响匹配；未运行的锁定条目永久保留，仅能通过「解锁全部」清空。

### 一、Rust 后端

**1. 新迁移 `src-tauri/migrations/0005_add_cleaner_lock.sql`**（在 `db/migrations.rs` 注册 version 5）：

```sql
CREATE TABLE IF NOT EXISTS cleaner_lock (
    fingerprint     TEXT PRIMARY KEY,  -- 规范化匹配键（小写）
    name            TEXT NOT NULL,
    cmdline         TEXT NOT NULL DEFAULT '',
    cwd             TEXT,
    exe             TEXT NOT NULL DEFAULT '',
    display_title   TEXT NOT NULL DEFAULT '',
    cmdline_summary TEXT NOT NULL DEFAULT '',
    locked_pid      INTEGER NOT NULL,  -- 锁定时的 PID（仅参考）
    create_time     TEXT NOT NULL DEFAULT (datetime('now'))
);
```

**2. 新 `services/cleaner_lock_service.rs`**（无 Tauri 依赖，接收 `&Pool<Sqlite>`，含单测）：
- `pub fn fingerprint(name, cmdline, cwd) -> String`：cmdline 非空 → `cmd:{lower(cmdline)}`；否则 cwd 有值 → `cwd:{lower(cwd)}|{lower(name)}`；否则 → `name:{lower(name)}`
- `async fn locked_map(pool) -> AppResult<HashMap<String, i64>>`（指纹 → 锁定条目 id）
- `list / add`（`INSERT OR IGNORE` 按指纹主键去重）/ `remove(id)` / `clear`
- 单测：指纹规范化（大小写不敏感、空 cmdline 回退、cmdline 截断一致性）、去重、增删清

**3. `models.rs`**：`CleanerLock`（`FromRow + Serialize`）、`CleanerLockInput`（`Deserialize`，字段取自 DevProcInfo 的指纹字段 + pid）

**4. `process/dev_scan.rs`**：`DevProcInfo` 增加 `locked: bool`、`lock_id: Option<i64>`（内部构造时默认 false/None）

**5. `commands/cleaner.rs`**：
- `scan_dev_processes` 返回前：取 pool → `locked_map` → 对每个进程计算指纹填充 `locked`/`lock_id`（DB 读失败降级为全未锁定，不影响扫描）
- 新增 4 个薄命令：`list_cleaner_locks` / `add_cleaner_lock(input)` / `remove_cleaner_lock(lockId)` / `clear_cleaner_locks`
- `lib.rs` invoke_handler 注册（cleaner 分组）

### 二、前端

**6. `types/cleaner.ts`**：`DevProcInfo` 加 `locked: boolean`、`lock_id: number | null`；新增 `CleanerLock` 接口

**7. `api/cleaner.ts`**：新增 4 个 invoke 包装（camelCase 顶层参数，input 内 snake_case）

**8. `stores/cleaner.ts`**（核心改造）：
- **删除** localStorage 读写与 `scan()` 中的「清理不存在 PID 并回写」逻辑；启动时一次性 `localStorage.removeItem` 旧 key（旧 PID 无法迁移为指纹，直接废弃）
- `lockedPids` Set 删除，`isLocked(p)` → 直接返回 `p.locked`
- `toggleLock(p: DevProcInfo)` 改异步：`p.locked ? removeCleanerLock(p.lock_id) : addCleanerLock(指纹字段)`，成功后更新本地 `processes` 对应条目
- `unlockAll()` → `clearCleanerLocks` + 本地刷新
- `toggleAllowKillIde()` 恢复保护时，对 locked 的 IDE 进程改为调 `removeCleanerLock`（保留现有语义）
- `lockedCount` 改为锁定**条目总数**（含未运行，维护一个 ref：抽屉打开时 `list` 一次 + 增删时更新）

**9. `components/cleaner/CleanerDrawer.vue`**：锁定按钮 `toggleLock(p.pid)` → `toggleLock(p)`；`handleUnlockAll` 确认文案/提示用条目总数

### 三、语义说明（写入代码注释）
- 指纹相同的多个进程实例（同命令行同目录）会被一并锁定/解锁——指纹无法区分实例，锁定语义为「按程序指纹锁定」，偏安全
- 未运行的锁定条目永久保留，仅「解锁全部」可清空（用户已确认轻量方案）
