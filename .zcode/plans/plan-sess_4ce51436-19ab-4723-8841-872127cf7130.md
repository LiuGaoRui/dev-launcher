# 修复计划：清理器进程锁定评审问题（H1 / M1 / M2 / M3 / L2 / L4）

## 修复范围
- **修复**：H1（指纹碰撞）、M1（计数不对账）、M2（后端不校验锁定）、M3（静默降级无日志）、L2（UTC 时间）、L4（模块排序）
- **不修**：L1（refreshLockCount 全表拉取——条目少、频率极低，新增 count 命令改动面 4 文件不划算）；L3（重启成功提示移除属有意降噪，维持用户意图）

---

## 1. H1：指纹改用完整命令行计算（核心修复）

思路：指纹由后端在扫描时基于**未截断** cmdline 一次算好，随 `DevProcInfo` 下发；前端锁定时原样回传，后端直接存储。展示字段继续用截断串，截断不再参与匹配。

**后端**
- `process/dev_scan.rs`
  - `fingerprint()` 从 cleaner_lock_service 迁入，`pub(crate)`（指纹属"进程识别"领域；services→process 依赖方向符合分层）
  - `DevProcInfo` 增加 `fingerprint: String` 字段，扫描循环中用 `cmdline_full`（截断前）计算
- `services/cleaner_lock_service.rs`
  - 删除本地 `fingerprint`，改引 `dev_scan::fingerprint`
  - `CleanerLockInput`（models.rs）增加必填 `fingerprint: String`；`add()` 直接存 `input.fingerprint`，不再自行计算
- `commands/cleaner.rs`：锁定标注改为 `locked.get(&p.fingerprint)`，删除扫描处的重复指纹计算
- 单测随迁；新增用例：两个前 400 字符相同、尾部不同的超长 cmdline → 指纹不同

**前端**
- `types/cleaner.ts`：`DevProcInfo`、`CleanerLockInput` 各加 `fingerprint: string`
- `stores/cleaner.ts`：`toLockInput()` 回传 `p.fingerprint`

**数据兼容**：不做旧数据迁移——截断版指纹无法反推完整 cmdline，且功能未发布（工作区未提交），开发期数据可重锁。在 0005 迁移注释中注明。

## 2. M1：lockedCount 对账

`stores/cleaner.ts` `toggleAllowKillIde`：保留乐观扣减（即时反馈），`Promise.allSettled` 完成后无论成败调用一次 `refreshLockCount()` 对账，消除删除失败导致的持久计数漂移。

## 3. M2：后端 kill / trim 强制校验锁定（纵深防御）

- `commands/cleaner.rs`：`kill_dev_processes` / `trim_dev_processes` 执行前读 `locked_map`；对每棵树的根 PID，从 `AppState.system()`（不刷新，用上次扫描缓存）取 cmd/cwd/name 计算指纹，命中锁定则跳过该树；进程不在缓存时按未锁定处理（维持现行为）
- dev_scan 提供 `pub(crate)` 辅助：从 `&System` + PID 提取指纹（内部复用 `join_cmdline`）
- `KillResult` / `TrimResult` 增加 `skipped_locked: u32`，`types/cleaner.ts` 同步；CleanerDrawer 结果消息体现"已跳过 N 个锁定进程"
- 持锁只做字段读取（微秒级），不阻塞 kill 执行

## 4. M3：池获取失败补日志

`commands/cleaner.rs` `scan_dev_processes` 中 `db::pool(&app)` 的 Err 分支加 `tracing::warn!`，与相邻 locked_map 降级策略一致。

## 5. L2：create_time 改本地时区

`migrations/0005_add_cleaner_lock.sql`（未发布，直接改文件，无需新迁移）：`DEFAULT (datetime('now'))` → `DEFAULT (datetime('now','localtime'))`。

## 6. L4：模块声明排序

`services/mod.rs`：`cleaner_lock_service` 移至字母序首位（detect_service 之前）。

## 风险与权衡
- `CleanerLockInput` 契约变更（新增必填 fingerprint）——前后端同批修改，无兼容窗口
- 旧锁定条目升级后失效（不迁移）——已声明，可接受
- M2 使 kill/trim 每次多一次 DB 读 + N 次指纹计算——量级为毫秒级，可忽略
