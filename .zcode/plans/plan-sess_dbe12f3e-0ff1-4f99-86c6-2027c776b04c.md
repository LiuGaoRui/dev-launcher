# 端口监控功能（Port Monitor）设计方案

## 目标

监控本机所有 TCP LISTEN 端口，重点暴露「AI 工具启动后遗留的异常存活服务」，压低系统端口和已配置项目端口的存在感。入口：TitleBar 右上角工具栏按钮（内存清理旁），红色角标显示可疑端口数，点击弹出居中大弹窗。

## 核心设计：端口分类 + 排序权重模型

后端为每个监听端口计算 `category`（7 档）+ `score`（0-100），**按 score 降序返回**，前端直接渲染。判定按固定优先级顺序（前者优先），保证可解释、无歧义：

| 优先级 | 分类 | score | 判定条件 |
|---|---|---|---|
| 1 | `system` 系统端口 | 0-9 | 占用者是系统进程（svchost/lsass/services/System/RuntimeBroker…）或 owner_pid 不可得（Windows 内核 http.sys 等） |
| 2 | `env_service` 环境服务 | 10-14 | 常驻服务进程（mysqld/postgres/redis-server/mongod/nginx/docker…）或知名服务端口（3306/5432/6379/27017/1433/5672/9092…） |
| 3 | `known_project` 已配置-托管 | 15-19 | 端口命中本工具项目 `expected_ports`，且该项目本工具托管运行中 |
| 4 | `known_project_external` 已配置-外部启动 | 20-29 | 端口命中 `expected_ports`，但进程为外部/AI 启动（附小标记） |
| 5 | `other` 其他 | 30-49 | 无法归类的非系统进程 |
| 6 | `dev` 开发端口 | 50-69 | 开发运行时进程（node/java/python/go/dotnet/deno/bun…）监听**知名 dev 端口**（3000/5173/8080/4200…）且有 IDE 父链（正常开发中） |
| 7 | `suspicious` 可疑 | 70-100 | 开发运行时进程监听**非项目配置**端口。加分项：孤立进程（父祖链无 IDE，AI CLI/终端遗留的典型特征）+8；随机高位端口（不在知名 dev 端口表，测试框架常用）+8；监听 0.0.0.0/[::] 对外暴露 +4；存活 >1 小时 +5 |

同 score 内次级排序：启动时间早者在前（遗留越久越可疑）→ 端口号升序。

复用 `dev_scan.rs` 现成能力（改为 `pub(crate)`）：`is_ide_process`/`is_orphan`/`is_dev_process`/`extract_display_title`/`extract_cmdline_summary`/`extract_project_path`——端口行直接展示「vite dev server」「my-app」等人类可读信息。

数据聚合：按端口号聚合，IPv4/IPv6 监听地址合并为 `addresses` 列表 + `listen_all_interfaces` 标记；owner 取首个关联 PID。

## 后端改动（Rust）

1. **新增 `src-tauri/src/process/port_scan.rs`**（纯函数层，含单测）
   - `enum PortCategory` + `struct ListeningPortInfo { port, addresses, listen_all_interfaces, owner_pid, process_name, exe, display_title, cmdline_summary, project_path, started_at, memory_bytes, category, score, orphan, random_port, matched_project_name, tree_pid_list }`
   - `scan_listening_ports(system, sockets, projects: &[(id, name, ports, last_pid)], registry_ids, self_pid) -> Vec<ListeningPortInfo>`：过滤 `TcpState::Listen` → 逐条分类评分 → 排序
   - 内置三张静态表：系统进程名、环境服务进程名/端口、知名 dev 端口；dev 运行时判定在 dev_scan 基础上扩展 python/go/dotnet/deno/bun 等
2. **修改 `src-tauri/src/process/dev_scan.rs`**：相关识别/提取函数 `private` → `pub(crate)`
3. **新增 `src-tauri/src/commands/port.rs`**：`list_listening_ports` 薄命令——拉 DB 项目全表（id/name/expected_ports/last_pid）→ `collect_tcp_sockets()`（复用，锁外）→ 持 system 锁 `refresh_processes_specifics` 后调 `scan_listening_ports`
4. **修改 `src-tauri/src/commands/mod.rs` + `lib.rs`**：注册新命令
5. 杀进程**复用现有** `kill_dev_processes`（已带 taskkill /F /T 杀树、自身/锁定护栏），无需新命令；无 DB 迁移

## 验证

- `cargo test`（port_scan 分类/评分/排序/地址合并单测）+ `cargo check`
- `pnpm typecheck`
- 手工验证：本机起一个 vite dev server 模拟 AI 遗留 → 弹窗中应出现在「可疑」顶部并带角标；MySQL 等服务应折叠在低档

## 风险与权衡

- **netstat2 拿不到部分系统端口占用者 PID** → owner_pid=None 统一归 `system` 档（折叠不显眼），符合预期
- **常驻 30s 轮询开销**：一次 socket 全表 + sysinfo 进程刷新，与 cleaner 打开时的 5s 轮询同量级，可接受
- **端口冲突场景**（服务进程占了项目配置端口）按判定优先级归入 env_service/system，不做冲突告警——probe_statuses 已有 running_abnormal 覆盖
- 仅监控 TCP LISTEN（UDP 无监听语义，dev server 均为 TCP）
