# ADR-001: 放弃 tauri-plugin-shell，自管进程

**状态**：已采纳
**日期**：阶段 0

## 背景

DevLauncher 需要启动用户配置的命令（如 `npm run dev`、`java -jar app.jar`），并能可靠地**杀死整棵进程树**（父进程 + 所有子进程）。

`tauri-plugin-shell` 是 Tauri 官方的进程执行插件，提供 `Command::new().spawn()`。

## 决策

**不使用 tauri-plugin-shell，改用 `tokio::process` + Windows Job Object 自管进程。**

## 理由

1. **杀树可靠性**：tauri-plugin-shell 在 Windows 下杀进程只能杀直接子进程。用户命令（如 `cmd /C npm run dev`）会产生多层子进程（cmd → node → 子 worker），杀不全会导致端口占用、僵尸进程。Windows Job Object 能保证杀掉 Job 内所有进程（含后代）。

2. **stdio 重定向**：我们要求 stdout/stderr 直接落盘到日志文件（避免 pipe 缓冲满导致进程阻塞）。自管进程可以精确配置 `std::process::Stdio::from(File)`，而 plugin 的 API 不暴露这种底层控制。

3. **PID 跟踪**：需要在 ProcessRegistry 中维护 root PID + Job Handle，供 monitor 模块查询 CPU/MEM、供 restart 使用。

4. **依赖最小化**：减少一个插件依赖。

## 代价

- 需要自己写 Windows Job Object 的 unsafe FFI 封装（约 150 行）
- 跨平台需要为非 Windows 预留 `process_group` 方案（MVP 仅 Windows）
- 无法享受 plugin 的快捷 API

## 实现要点

```
process/
├── spawn.rs      → tokio::process::Command + creation_flags + stdio→File
├── job_object.rs → Windows Job Object（unsafe，AssignProcess + TerminateJobObject）
├── registry.rs   → ProcessRegistry<project_id, (child, job_handle)>
└── tree.rs       → sysinfo 收集后代 PID（用于 monitor）
```

## 附录：阶段 2 实现细化（补充）

阶段 2 落地时发现并确认了若干实现细节，补充如下：

### 1. CREATE_SUSPENDED 不可行
原设想「CREATE_SUSPENDED → assign → ResumeThread」无法实现：std/tokio 的 `Command::spawn()` 在返回前就关闭了主线程句柄（`hThread`），调用方拿不到线程句柄也就无法 `ResumeThread`。

**改用 spawn-then-assign**：spawn 后立即 `AssignProcessToJobObject`。存在微秒级竞态（进程已运行但尚未入 Job），但此时进程仍在 loader 初始化阶段，未执行用户代码；且 `KILL_ON_JOB_CLOSE` 保证句柄关闭时整树回收。实践中可靠，是 Windows 进程管理器的通用做法。

### 2. windows crate Cargo features 修正
- `CreateJobObjectW` 需 `Win32_Security`（即便传 `None` 安全属性也要此 feature 编译）
- `Win32_System_ProcessStatus` 未被任何 Job API 使用，已移除

### 3. JobHandle 用 `Owned<HANDLE>` 做 RAII
- drop 自动 `CloseHandle` → 触发 `KILL_ON_JOB_CLOSE` 杀全树
- HANDLE 含裸指针非 Send/Sync，`JobHandle` 显式 `unsafe impl Send/Sync`（经 Mutex 串行访问，安全）

### 4. active_processes 轮询 + try_wait 延迟
- `stop` 用 `QueryInformationJobObject(BasicAccounting)` 读 `ActiveProcesses` 轮询归零（最多 5s）
- Job 终止后 tokio `Child::try_wait()` 可能短暂返回 `None`（OS 已回收但句柄未感知），需轮询等待而非单次断言
- `Owned<HANDLE>` 调用 FFI 时用 `handle.clone()`（Owned 支持 clone，复用计数）

### 5. stdout/stderr 落盘
对同一日志文件开两个独立 append 句柄（`Stdio::from` 会 move File，不能复用），OS 负责交错写入。
