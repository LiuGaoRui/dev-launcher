# ADR-006: 日志订阅生命周期与项目隔离

**状态**：已采纳
**日期**：2026-09-11
**取代**：ADR-002 中「依赖前端 GC Channel 自动退订」的部分

## 背景

用户反馈两类日志串流问题：

1. **跨项目串流**：打开 A 项目日志后再打开 B 项目，A 的日志内容混入 B 的面板；
2. **跨类型串流**：切换「启动日志 / 构建日志」Tab 时，两种日志混在同一个面板。

排查后确认有两条独立成因：

### 前端：共享单缓冲 + 订阅未真正失效

`useLogStore` 是 Pinia 单例，全局只有一份 `lines` 文本缓冲和一个 `channelRef`。
`stopLive()` 只把引用置 `null`，既不关闭 Channel 也不校验消息归属：

- 显式退订缺失：ADR-002 假设「引用置 null → GC → 后端 `send()` 失败 → task 退出」，
  但 GC 时机不确定，窗口期内旧 tail task 仍在推送；
- `onmessage` 闭包捕获的是 store 的共享 `lines`，没有任何「这条消息属于哪个
  项目 / 类型 / 订阅」的判断，于是旧推送被追加进新缓冲。

### 后端：日志目录以项目名为键

路径为 `{logs_root}/{sanitize_name(project.name)}/{start|build}.log`，而
`project.name` 在库中**没有 UNIQUE 约束**。同名项目、或 sanitize 后同名的项目
（如 `a/b` 与 `a:b` → 都是 `a_b`）会共用同一文件，互相 truncate 并交错追加。

## 决策

1. **日志目录改用项目 id（DB 主键）**：`{logs_root}/{project_id}/{start|build}.log`。
   旧 `{项目名}` 目录弃用，不迁移。
2. **订阅显式生命周期**：`subscribe_log` 返回后端分配的 `sub_id`；新增
   `unsubscribe_log(sub_id)` 命令。不再依赖 Channel GC。
3. **推送带来源标识**：`LogChunk` 增加 `sub_id` 字段，前端据此丢弃过期订阅的推送。
4. **前端 token 守卫**：每次 `startLive` 递增 token，`onmessage` 校验
   `token` 与 `chunk.sub_id` 双重匹配后才写入缓冲。
5. **启动/构建失败可观测**：先 truncate 再 spawn 的路径上，spawn 失败时把错误原因
   写入日志文件，避免用户看到空日志。
6. **per-project 启动锁**：`start_project` 的「校验 → truncate → spawn → 入 registry」
   用 `tokio::sync::Mutex` 串行化，消除并发启动导致的二次 truncate。

## 理由

- **id 为键从根上消除碰撞**，且项目改名不再丢日志；代价是旧路径日志不可见（可接受）。
- **显式退订比 GC 可靠**：取消延迟上限为一个轮询间隔（250ms），语义确定、可测试。
  取消用 `AtomicBool` 标志而非 `JoinHandle::abort`，让 task 在轮询节点干净退出，
  不会在 `Channel::send` 中途被强杀。
- **`sub_id` + token 双重校验**：即使后端取消存在 250ms 延迟，前端也绝不会把过期
  推送写进当前缓冲 —— 正确性不依赖后端时序。
- **不加新依赖**：id 用 `AtomicU64`，取消标志用 `AtomicBool`，无需 `uuid` / `tokio-util`。

## 代价

- 已有 `{项目名}` 目录下的日志不再被读取（用户可手动删除）。
- 订阅取消最坏有 250ms 延迟（有前端 token 守卫兜底，不影响正确性）。
- `AppState` 增加两个字段（`log_subs`、`start_locks`），启动锁 map 按项目数增长（有界）。

## 实现

```rust
// logs/subscription.rs — 订阅注册表
let (sub_id, cancel) = registry.register();
tail::spawn_tail_task(log_path, sub_id, cancel, registry, on_event);  // 退出时 registry.finish(sub_id)
```

```rust
LogChunk { sub_id, offset, text }   // 推送携带来源订阅 id
```

```typescript
// stores/log.ts — token 守卫
const myToken = ++seq
activeToken = myToken
channel.onmessage = (chunk) => {
  if (activeToken !== myToken) return
  if (activeSubId !== null && chunk.sub_id !== activeSubId) return
  lines.value += chunk.text
}
// stopLive：seq++（作废旧回调）+ unsubscribeLog(activeSubId)
```
