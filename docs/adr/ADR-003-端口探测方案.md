# ADR-003: 端口探测用 netstat2 + TcpStream 双重检测

**状态**：已采纳
**日期**：阶段 0

## 背景

DevLauncher 需要判断项目配置的 `expected_ports`（如 `["8080","5173"]`）是否真正在监听，以区分 Running / RunningAbnormal 状态。

## 决策

**用 `netstat2` 查监听者 + `std::net::TcpStream::connect` 探活，双重检测。**

## 理由

1. **netstat2 找监听者**：解析操作系统 socket 表，能拿到 `{port, pid, state}`。用于：
   - 判断端口是否被监听
   - 关联监听者 PID（判断是否属于当前项目的进程树）

2. **TcpStream 探活**：netstat2 可能因为权限拿不到全部信息（Windows 下 UAC），用 `TcpStream::connect_timeout` 做二次确认更可靠。

3. **为什么不只用 netstat2**：某些情况下端口处于 LISTEN 但应用未就绪（如 Spring Boot 启动中 bind 了但还没处理请求）。MVP 不做 HTTP 健康检查（P1），TcpStream 探活是最简单的补充。

## 流程

```
get_runtime_status(project_ids):
  1. netstat2 获取全系统 socket 表（缓存 2s）
  2. 对每个 project 的 expected_ports:
     a. 查表：port 是否在 LISTEN？
     b. 如是 → TcpStream::connect_timeout(500ms) 二次确认
     c. 如是 → listening=true, owner_pid=表中pid
  3. 返回 RuntimeStatus
```

## 代价

- netstat2 调用有开销（约 5-20ms），通过 2s 缓存 + 批量查询缓解
- TcpStream 探活可能被防火墙拦截（误判为未监听），设短 timeout（500ms）
