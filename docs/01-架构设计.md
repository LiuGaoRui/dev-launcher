# 01 - 架构设计

> 本文档描述 DevLauncher 的分层架构、IPC 边界、状态管理与错误模型。详细到模块文件名级别，可直接据此实现。

## 一、三层架构

```
┌───────────────────────────────────────────────────┐
│  表现层 (Vue 3 + Element Plus + Pinia)             │
│  项目列表 / 状态监控 / 日志查看 / 分组管理          │
└────────────────────┬──────────────────────────────┘
                     │ Tauri IPC (invoke / Channel)
┌────────────────────▼──────────────────────────────┐
│  系统能力层 (Rust)                                  │
│  commands (薄) → services (业务)                   │
│  → process / monitor / logs / db (系统能力)        │
└────────────────────┬──────────────────────────────┘
                     │ tauri-plugin-sql
┌────────────────────▼──────────────────────────────┐
│  数据层 (SQLite)                                    │
│  group / project / log_ref / dependency            │
└───────────────────────────────────────────────────┘
```

## 二、IPC 边界原则

- **Rust `commands/` 层**：薄层，只做参数解包 + 调 `services/` + 错误转换。不写业务逻辑。
- **Rust `services/` 层**：业务编排，**不依赖 Tauri**（便于单测）。如 `lifecycle_service::restart_project` 串接 stop → wait → start。
- **Rust `process/`、`monitor/`、`logs/`、`db/`**：纯系统能力封装，被 services 调用。
- **Vue `api/` 层**：薄包装，统一 `invoke` 调用与错误处理，组件不直接 invoke。
- **Vue `stores/`**：状态持有 + 业务编排（如一键发布 = stop → build → start 串行调用 api）。
- **Vue `composables/`**：组件与 store 的桥梁（如 `useProjectMonitor` 启停 3s 轮询）。

## 三、全局状态 (Tauri State)

```rust
// src-tauri/src/state.rs
pub struct AppState {
    pub registry: Mutex<ProcessRegistry>,  // HashMap<i64, ManagedProcess>
    pub sys: Mutex<sysinfo::System>,       // 复用，避免每次新建
    pub db_path: PathBuf,                  // SQLite 文件路径
    pub logs_root: PathBuf,                // {app_config_dir}/logs
}
```

`ManagedProcess` 持有：`root_pid: u32`、`job_handle: HANDLE`（Windows）、`log_path: PathBuf`、`started_at: DateTime`。

## 四、状态机

```
        start()                       port not listening
  ┌──────────────┐              ┌──────────────────────┐
  │              ▼              │                      ▼
┌─┴────┐      ┌─────────┐      ┌─────────┐      ┌──────────────┐
│Stopped│◄────│Starting │      │ Running │─────►│Running(Abn.) │
└──────┘ stop └─────────┘      └────┬────┘      └──────┬───────┘
     ▲                              │ stop             │ port ok
     │            ┌─────────────────▼                  │
     │            ▼                                    │
     │      ┌──────────┐                               │
     └──────│Stopping  │◄──────────────────────────────┘
            └──────────┘
```

| 状态 | 判定 |
|---|---|
| Stopped | registry 中无记录 + sysinfo 找不到 PID |
| Starting | 调了 start 但端口未 ready（< 30s 宽限） |
| Running | PID 存活 + 至少一个 expected_port 监听 |
| Running(Abnormal) | PID 存活 + 所有 expected_port 未监听 |
| Stopping | 调了 stop，等 Job 终结 |

宽限期（Starting → Abnormal）：**30 秒**（可配置）。

## 五、错误模型

```rust
// src-tauri/src/error.rs
#[derive(Debug, thiserror::Error, serde::Serialize)]
pub enum AppError {
    #[error("project not found: {0}")]
    ProjectNotFound(i64),
    #[error("project already running: {0}")]
    AlreadyRunning(i64),
    #[error("project not running: {0}")]
    NotRunning(i64),
    #[error("spawn failed: {0}")]
    SpawnFailed(String),
    #[error("job object error: {0}")]
    JobObject(String),
    #[error("db error: {0}")]
    Db(String),
    #[error("io error: {0}")]
    Io(String),
    #[error("invalid input: {0}")]
    InvalidInput(String),
}

pub type AppResult<T> = Result<T, AppError>;
```

Tauri command 返回 `AppResult<T>`，前端拿到 `{ code, message }` 形式的错误。前端 `api/invoke.ts` 统一捕获并 `ElMessage.error(message)`。

## 六、配置路径

| 用途 | 路径 |
|---|---|
| 数据库文件 | `{app_config_dir}/devlauncher.db` |
| 日志根目录 | `{app_config_dir}/logs/` |
| 单项目日志 | `{logs_root}/{project_name}/{YYYYMMDD}.log` |

`app_config_dir` 通过 `app.path().app_config_dir()` 拿（Windows 上为 `C:\Users\{user}\AppData\Roaming\devlauncher\`）。
